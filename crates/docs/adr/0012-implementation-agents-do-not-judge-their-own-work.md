# Implementation Agents do not judge their own work

Implementation Agents dispatched by Forge reported their own Check outcome and repeatedly stopped after partial work through sanctioned paths: `interrupted`, `fail/complete` with "what remains", and Continuations. Tightening instructions moved the escape from one disposition to another; the outcome verb itself was the escape hatch, and every self-reported stop consumed retries or remediation cycles.

Remove the verdict from the Implementation Agent. Its only finishing action is a Review Request, which records the Implementation Check's pass on committed, clean evidence and hands off to the Task's existing review Checks, which remain the sole judges and keep their handback and human-input outcomes. When the Agent ends a turn without a Review Request, Forge nudges the same live session through Herdr, bounded per Assignment (three consecutive nudges without a new commit or twenty in total place a Dispatch Hold). A blocked Agent explains itself with a comment; the operator answers by resuming with an explanation that Forge delivers as the next nudge. Agent-submitted Continuations are removed. Every post-bootstrap prompt is durably recorded before sending and an uncertain delivery holds rather than retries, extending ADR-0008's prompt rule to all prompts. Herdr `done` means a finished turn, not a lost Agent.

The rule is enforced in the application layer, so every entry point (RPC, CLI, in-process callers) refuses verdicts from an Implementation Assignment; tests that need an Implementation outcome go through a Review Request or a review Check.

Considered and rejected: a Forge-run deterministic gate alone (Forge runs no builds or tests and acceptance criteria are behavioral; a non-empty diff would have accepted partial slices); a separate supervisor agent (review-implementation already judges the Task); counting each committed slice as a review round (it exhausts the three-handback cap one slice at a time); detecting completion from the Agent's final message (Forge cannot read Agent output); and keeping one Implementation Agent alive across reviews (it conflicts with one open Assignment per Task, one attempt per Assignment and capacity counting).

The trade-offs: the Implementation Pass now means "submitted for review" rather than "judged met"; a false Review Request costs a review round and a remediation cycle; nudged sessions hold capacity while idle on a hold; and each review round starts a fresh Agent that re-reads its context.

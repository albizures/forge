## Real-provider gate

Operator-authorized on 2026-11-21: billed `openai/gpt-4.1` calls, an owner-only key file passed
by path, scratch Workspaces under `/tmp`. Harness: `crates/cli/tests/durable_real_provider.rs`
(procedure in [development verification](../development.md#real-provider-release-gate)). It
uses the production composition, the real host, the shipped runner entry and the real CLI and
daemon, with separately pinned Implementation and Review profiles (the reviewer gets only
`read` and `bash`). The only test-only substitution is launch eligibility.

Asserted per run: matched Revision and component hash on the Launch; authenticated bootstrap;
an accepted Implementation Outcome whose output commit adds exactly `hello.txt`; no Review
before the Implementation is retired; capacity released from proof; a fresh Review Assignment
bound to exactly that commit; an accepted Review Outcome with the same evidence; no
`git add`/`git commit`/`write`/`edit` in the Review transcript; worktree clean at the output
commit; no API-key-shaped token in runtime storage or the repository.

Run 2: the first OpenAI request failed at connection level after 0.5 s
(`Connection error.: AggregateError (ETIMEDOUT)`), before any token or tool call. With provider
retries disabled, the Implementation went Blocked with Missing Outcome, capacity stayed
reserved and no Review was dispatched: the specified safe behaviour.

Earlier runs on pre-release commits informed the design:

- **No credits** (`bacf2ef`): the provider refused the first call; Forge recorded Missing Outcome
  and kept capacity.
- **Shared profile** (`02e5950`): a single profile let the reviewer act as an implementer.
  The harness now uses separate profiles and independence assertions; Forge's own evidence
  re-observation would have refused a changed Review commit.
- **Effect-free failures** (`9ac67f6`): a routine tool error (reading `.git/HEAD`, a file in a
  worktree) was treated as an interrupted effect and ended the Assignment. Fixed in `9a7bb77`
  and `e968686` (metered execution environment); independently reviewed twice.
- **Unsubmitted Outcomes** (`9a7bb77`): reviewers answered in prose or falsely claimed a
  submission. Fixed in the harness profiles with one exact submission command; recorded as a
  profile-authoring limitation.
